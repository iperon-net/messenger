# 04-edit-time-limit — скрытие «Редактировать» после окна правки

**Статус:** in progress (с 2026-11-17)

## Цель

Сервер запрещает правку своего сообщения через 48 часов (`chatEditWindow`,
`internal/services/chats.go:53` на сервере; окно завязано на S3-архив истории —
архивное сообщение неизменяемо, валидация требует
`chatHistoryArchive.after >= 48h`). Клиент об этом не знает и показывает
«Редактировать» всегда для своих сообщений — пользователь нажимает, пишет
текст, а сервер отвечает `PERMISSION_DENIED`. Нужно: срок приходит с сервера
в `ClientConfig`, и по истечении окна пункт «Редактировать» не показывается
в меню сообщения (Cupertino, Material, десктоп-шорткат ↑).

## Принятые решения

- **Срок берём из `ClientConfig`, не дублируем константой на клиенте** —
  ответ пользователя. Сервер отдаёт `int32 chatEditWindowHours = 10` в
  `ClientConfig.Response` из одного источника — `chatEditWindow` из
  `internal/services/chats.go`, чтобы значения не разъехались. Клиент читает
  через `Settings` (паттерн существующих геттеров: `_serverConfig?.поле ?? дефолт`,
  fallback 48 ч — работает офлайн и до первого ответа сервера, кэш
  `ClientConfigSync` уже в `device.db`). Альтернатива отклонена: константа
  на клиенте рассинхронится при смене срока на сервере.
- **Повторяем серверные исключения, а не единое окно** — окно действует
  только в личных чатах и группах (серверная проверка
  `!chat.IsSelf() && time.Since(message.Date) > chatEditWindow`,
  `internal/services/chats.go:1273`); каналы — без окна, по правам
  (`checkChannelEdit`, «как в Telegram»); Saved Messages (`chat.isSelf`) —
  без окна (не архивируется: «правка без срока»,
  `internal/services/chats_history_archive.go:89-92`). Иначе клиент скрыл бы
  пункт, который сервер разрешит. Альтернатива «везде 48 ч» отклонена:
  расходится с сервером.
- **Гейт — в `ChatCubit.canEdit`** (`lib/cubit/chat/chat_cubit.dart:1148`),
  а не в экранах: оба меню (`chat_cupertino.dart:998`,
  `chat_material.dart:1097`), десктоп ↑ `_editLast()`
  (`chat_material.dart:504`) и `edit_media` уже вызывают
  `canEditMessage` → пункт скрывается везде сразу и синхронно.
  Альтернатива «проверка в каждом меню» отклонена: дублирование,
  легко разъезжается.
- **Пункт скрывается полностью, не дизейблится** — из формулировки задачи
  («не нужно в меню показывать»).
- **Окно не применяется к неотправленным (outbox) сообщениям**
  (`randomIDOfLocal(id) != null`, хелпер уже есть в
  `lib/chats/edit_media.dart`) — они ещё не дошли до сервера, серверное окно
  на них не действует; черновик, висящий >48 ч, остаётся правимым.
  Scheduled-сообщения трогать не нужно: их `date` в будущем, разница
  отрицательная, окно не срабатывает.
- **Путь отправки правки при серверном отказе не трогаем** — ответ
  пользователя («только меню»): граничный случай «открыл меню до истечения
  окна, отправил после» остаётся как есть (ошибка в unhandled future —
  существующее поведение, не этого этапа).
- **Демо-чаты — без отдельной логики**: гейт общий в `ChatCubit`, даты
  демо-сообщений — от старта сессии (`date: now`), лимит применится
  естественно и ничего в демо не ломает.
- Слои: сервер (proto + `internal/api/client_config.go`) → клиент (регенерация
  прото → `Settings`-геттер → гейт в `ChatCubit`). Миграций SQLite нет.
  Прото правится в обоих репо (копия `client_config_v1.proto` сервер ↔ клиент,
  серверу `task gen`, клиенту — точечный protoc по конвенции AGENTS.md).
