# Bootstrap-конфиг вместо Remote Config

Статус: 2026-10-30, план. Не начато.

## 1. Задача

После этапа 5б админки (`docs/plans/admin-panel.md`, клиент `v0.0.573`) флаги и лимиты
приходят с сервера (`ClientConfig`, `lib/client_config.dart`), а Remote Config остался
запасным вариантом. Убрать его целиком мешают ключи, которые сервер отдать не может —
они нужны **до** подключения к нему:

| Ключ Remote Config | Что это | Куда |
|---|---|---|
| `API_HOST` / `API_PORT` / `API_SECURE` | адрес gRPC-сервера | в bootstrap-файл |
| `PUBLIC_KEY_EDDSA_FINGERPRINT` | отпечаток ключа сервера (сейчас в клиенте **не используется**, см. `docs/plans/on-premise.md` §3) | в bootstrap-файл — задел под пиннинг |
| `PHONE_NUMBER_MODERATION_APPLICATION_STORE(_ENABLE)` | тестовые номера | удалить: сервер сам отвечает `fixedCode` на `AUTH_CALL_PASSWORD` |
| флаги, тайминги звонков, URL эмодзи, client_id Яндекса | — | уже с сервера (`ClientConfig`), из Remote Config — удалить |

Решение: подписанный статический файл по известному адресу — переезд сервера и смена
ключа без новой сборки, без Firebase.

## 2. Файл

`https://download.iperon.net/config.json` (nginx на alica, тот же, что раздаёт релизы
macOS); копия — на GitHub Releases этого репо (отдельный тег, например `bootstrap`).

```json
{
  "serial": 7,
  "issuedAt": 1793260800,
  "api": [
    {"host": "staging.iperon.net", "port": 443, "secure": true}
  ],
  "serverKeyFingerprint": "7abfc2a7e8ea09ae384bdeb855cfeae24d60bfac3646046e754fddc8d5ab604d",
  "signature": "<base64 Ed25519 от канонического JSON без поля signature>"
}
```

- `serial` — монотонный номер: клиент не принимает файл с `serial` меньше закэшированного
  (иначе можно подсунуть старый подписанный конфиг со старым адресом).
- `api` — список: первый — основной, остальные — запасные (резервный сервер, другой
  домен на случай блокировки).
- Подпись — от канонической сериализации (ключи по алфавиту, без пробелов) всех полей,
  кроме `signature`. Публичный ключ Ed25519 зашит в сборку, приватный на серверах не
  лежит.

## 3. Безопасность

- **Подпись обязательна.** Без неё подмена файла (взлом хостинга, DNS, чужой
  сертификат) уводит всех клиентов на чужой сервер; HTTPS от этого не спасает.
  Неподписанный / с неверной подписью файл — игнорируется (лог в Talker).
- **Откат** — `serial` (см. выше).
- **Источник не доверенный**: копии на GitHub Releases / S3 проверяются той же подписью.
- **Ключ подписи** — секрет GitHub; файл подписывает workflow (вручную, `workflow_dispatch`
  с параметрами), а не человек на ноутбуке. Ротация ключа подписи — только новой сборкой
  (в сборке можно держать два публичных ключа: текущий и следующий).

## 4. Клиент

Новый `BootstrapConfig` (`lib/bootstrap_config.dart`), читается через `Settings`
(`apiHost` / `apiPort` / `apiSecure` / `serverKeyFingerprint`), как сейчас Remote Config.

Порядок значений: `.env` (debug) → кэш файла в `device.db` → зашитое в сборку.

1. **Старт.** `Settings` берёт адрес из кэша (`device.db`, новая таблица
   `bootstrapConfig`: JSON файла + `serial`, одна строка — миграция `DeviceDatabase`).
   Кэша нет (первый запуск) — значения из сборки (`_defaults`). Подключение не ждёт сети
   до файла.
2. **В фоне** (`startAccountServices` и раз в сутки): скачать файл (`http`, таймаут 5 с),
   по очереди с адресов-зеркал до первого валидного; проверить подпись
   (`package:cryptography`, Ed25519) и `serial`; записать в кэш. Новый адрес применяется
   к следующему подключению стрима (`API` пересоздаёт `ClientChannel` при смене
   адреса).
3. **Сервер не отвечает** (несколько неудачных подключений подряд): перекачать файл мимо
   суточного интервала и пробовать следующий адрес из `api`.
4. **Мультиаккаунт / on-premise.** Файл описывает только «наш» сервер. Аккаунты на
   сервере заказчика (`docs/plans/on-premise.md` §3) хранят свой адрес в `accounts` и
   файл не используют; формат `api` позволяет позже добавить справочник.

Офлайн: файл не скачался — работаем с кэшем, ничего не показываем пользователю.

## 5. Удаление Remote Config

Вместе с этапом клиента:
- `lib/settings.dart`: убрать `remoteConfig`, `forceFetchRemoteConfig`, `_getString/_getInt/_getBool`
  через Firebase — значения из `_defaults` (как сейчас на десктопе, `AppPlatform.hasFirebase`).
- Экран «Разработчик → Remote Config» (`lib/screens/settings/developer_remote_config.dart`)
  заменить на «Bootstrap-конфиг»: текущий `serial`, адрес, «Обновить сейчас».
- `AuthCubit`: ветка тестовых номеров по списку из Remote Config и кнопка «вставить номер»
  в debug (`auth_{cupertino,material}.dart`) — удалить.
- Пакет `firebase_remote_config` — из `pubspec.yaml`. Firebase остаётся (Crashlytics, FCM).
- CLAUDE.md, раздел Settings / config.

**Консоль Firebase** — параметры Remote Config не трогать, пока живы сборки до `v0.0.573`
(они читают флаги и тестовые номера только оттуда, экрана «Обновите приложение» у них
нет). iOS — только TestFlight, сборка живёт 90 дней: `v0.0.572` загружена 2026-10-29 →
ориентировочно до 2027-01-27. Android-сборки распространяются вручную — уточнить.

## 6. Этапы

1. **Скрипт и файл.** `scripts/bootstrap_sign.dart` (генерация ключа, подпись, проверка);
   workflow `bootstrap.yaml` (`workflow_dispatch`: host/port/secure/fingerprint →
   подписанный `config.json` → nginx на alica + GitHub Release `bootstrap`); location в
   nginx (`Cache-Control: max-age=300`).
2. **Клиент.** `BootstrapConfig` + кэш в `device.db` + переключение адреса в `API`;
   тесты: подпись (верная / чужая / испорченная), `serial` (откат), выбор зеркала, разбор.
3. **Удаление Remote Config** (§5). Можно в той же сборке, что и этап 2.
4. **Позже:** пиннинг ключа сервера по `serverKeyFingerprint` (проверка ML-DSA/EdDSA-ключа
   из ответа сервера) — отдельной задачей вместе с on-premise.

## 7. Открытые вопросы
