# Тестирование на реальных устройствах

Статус: 2026-10-24, план, не начато. Задача — проверять звонки, пуши, группы и каналы на
реальных телефонах одной командой, а не вручную по разрозненным чеклистам. Сводный
сценарий групп и каналов — разделы 4–5, они же служат ручным чеклистом, пока автоматизации
нет.

## 1. Идея

Почти любой сценарий «двух устройств» можно свести к **одному телефону + боту**:

- **Бот `testpeer`** (сервер, `cmd/testpeer`) — настоящий клиент протокола на Go: входит
  тестовыми аккаунтами, держит стрим, по команде звонит, пишет, создаёт группы и каналы,
  меняет права, ставит реакции. Ролей несколько (владелец, админ, участник, посторонний),
  поэтому бот держит сразу 3–4 аккаунта.
- **Телефон** — тестовый аккаунт «я». Сценарий двигает приложение (Patrol на Dart:
  тапы, системные уведомления, разрешения) и состояние устройства (`adb`: свернуть,
  выгрузить, экран блокировки, без сети).
- **Проверка** — три слоя:
  1. экран телефона (Patrol: виден текст / баннер / цифра);
  2. системное уведомление (`adb shell dumpsys notification`, Patrol `notifications`);
  3. логи стенда в Loki (через Grafana MCP или HTTP API): «отправлено ли», чтобы отличать
     «сервер не послал» от «телефон не показал».

Второй реальный телефон нужен только там, где важна сама платформа с обеих сторон
(медиа звонка, iOS ↔ Android) — такие пункты помечены **[2 устр.]** и остаются ручными.

## 2. Инфраструктура

### 2.1. Тестовые аккаунты на стенде

- Вход ботом без звонка на номер. Сейчас без звонка входит только один номер
  (`phoneNumberModerationApplicationStore` — ревьюер стора). Нужен конфиг
  `testAccounts: [{phone, code}]` — **только на стенде** (на проде пусто), тем же путём
  `AUTH_MODERATION_APPLICATION_STORE`.
- 5 номеров: `me` (телефон), `owner`, `admin`, `member`, `stranger` (бот). Профили с
  именами и аватарами, `me` и `owner` — в контактах друг у друга, `stranger` — нет.
- Сброс между прогонами: бот удаляет созданные им группы/каналы и личные чаты с `me`
  (`testpeer reset`), чтобы сценарии не зависели от прошлых прогонов.

### 2.2. Бот `testpeer`

- Go, в репозитории сервера; переиспользует `internal/crypto` (Syncer, пуш-крипта) и
  `circl` для клиентской половины обмена ключами (ML-KEM decapsulate, проверка ML-DSA).
- Состояние аккаунтов (session, sharedKey/salt) — в локальном файле, чтобы не логиниться
  каждый прогон.
- **HTTP-управление** `testpeer serve :8090`: `POST /call {from, to, video}`,
  `/hangup`, `/send {from, chat, text, mention?}`, `/group/create`, `/channel/create`,
  `/post`, `/react`, `/poll/vote`, `/admin/set`, `/ban`, `/invite`, `/join` и т.д. Тест на
  телефоне ходит в бот по Wi-Fi (адрес ноутбука — через `--dart-define`).
- Ответ бота — id созданного (chatID, messageID), чтобы тест мог открыть ссылку или чат.
- CLI поверх того же API — для ручных проверок без Patrol.

### 2.3. Сценарии на телефоне

- **Android (первым):** сделан на `adb` без Patrol (см. этап 2 в разделе 7). Исходный
  вариант — Patrol (`patrol test`) — Dart-тест + доступ к системному UI
  (уведомления, экран звонка ConnectionService, разрешения, «Домой», блокировка).
  Состояния устройства, которые Patrol не умеет, — `adb` из раннера.
- **iOS (позже):** Patrol на подключённом iPhone. Ограничения: VoIP-пуш будит только
  release/TestFlight-подобную сборку (debug из выгруженного не будится), экран CallKit —
  системный (springboard) и в автоматизации нестабилен. Поэтому на iOS сначала
  автоматизируем всё, кроме входящего из выгруженного состояния, а его оставляем ручным.
- Раннер `tool/device_test.sh`: поднять бота, `flutter build` (profile) + установить,
  прогнать набор, собрать скриншоты/логи Patrol и выдержку Loki за время прогона.

### 2.4. Логи стенда

Короткий помощник (`tool/loki_check.dart` или запрос через Grafana MCP): «за окно прогона
есть строки X с полями Y». Пример — call-пуш: `push: dispatching call push` с
`fcmTargets ≥ 1`, затем `push: fcm sent`.

## 4. Группы (срез 3, `chats-groups.md`)

Обозначения: **Б** — делает бот, **Т** — делает телефон; «проверить» — на телефоне,
если не сказано иначе. Каждый блок дополнительно прогоняется **без сети** на телефоне
(авиарежим через `adb`): действие, требующее сервера, честно говорит «Нет соединения»,
ничего не «прыгает» назад, после возврата сети всё догоняется.

### 4.1. Базовая группа (3.1)

Проверено 2026-10-24 ботом (`testpeer group create` / `send -chat`, Android, приложение
выгружено): группа с телефоном в участниках создалась, сообщение и @-упоминание пришли пушами.
- Т создаёт группу (название, аватар, участники owner+member) → у Б она появилась,
  служебное «создал группу».
- Б пишет → у Т имя и аватар отправителя, непрочитанные, ✓✓ у Б после прочтения Т.
- Т свёрнут → Б пишет → пуш «Группа: Имя: текст», бейдж = 1 чат (4.5).
- «Изменить» название/описание/аватар (Т) → Б видит, служебные сообщения.
- «печатает…» от Б в группе — у Т с именем.
- Выход (Т), удаление группы владельцем (Б) → у Т группа пропала.
- Приватность «Кто может добавлять меня в группы» = «Мои контакты» → stranger не может
  добавить Т.

### 4.2. Роли и права (3.2)

Проверено 2026-10-24 ботом (Android): админ с частью прав (удаление чужих, закреп «для всех»)
— ровно эти пункты в меню; роль участника «Только чтение» — поля ввода нет; `defaultRole` —
роль только **вступающих** (уже вступившие её не получают); исключение с блокировкой — группа
пропала, по ссылке не пускает; разбан — вступил снова. Звание в чужих пузырях — после кэша
админов (`Members.admins`, клиент `e0cea43`), на устройстве ещё не проверено; «Передать
владение» — вручную.
- Б (owner) назначает Т админом с частью прав → у Т ровно эти пункты в меню; звание в
  пузыре.
- `defaultRole` «Чтение» → у участника нет поля ввода.
- Исключить / забанить Т → Т теряет чат, повторно по ссылке — «banned»;
  «Заблокированные» группы, разбан.
- Удаление чужого сообщения админом, закреп «для всех».
- «Передать владение» с облачным паролем (вручную: пароль).

### 4.3. Вступление (3.3)

Проверено 2026-10-24 ботом (Android + iOS): публичная группа (`@username`) находится в
«Глобальном поиске», предпросмотр, «Вступить»; ссылка с одобрением — заявка у бота с кодом
ссылки, после одобрения в группе; «Скрыть историю» — вступивший после включения видит только
новые сообщения; ссылка на одно вступление — второй раз «ссылка недействительна или устарела».
- Публичная группа с `@username` → Т находит в «Глобальном поиске», предпросмотр,
  «Вступить».
- Частная по ссылке, ссылка с лимитом / сроком / одобрением → заявка у Б, одобрение,
  Т в группе.
- «Скрыть историю» → вступивший Т не видит старых сообщений и их правок/реакций.
- `iperon.net/<group>` и `+code` открываются из чата и извне (deep link через `adb am start`).

### 4.4. Сообщения в группе (3.4)

Проверено 2026-10-24 ботом (Android + iOS): упоминание пробивает выключенный звук (обычное —
без пуша); кнопка «@» ведёт к упоминанию за экраном (исправлено — строка считалась
просмотренной, едва построившись, `36166df`); реакции бота на моё сообщение и пуш о них (в
заглушённом чате пуша нет); викторина — верный ответ после голоса; медленный режим — второе
сообщение ждёт и уходит само; правка с новым упоминанием — пуш только упомянутому;
«Новичкам — без ссылок и медиа» — текст можно, ссылку и фото нет; «Скрыть участников» —
не-админ видит только владельца, служебных «вышел / вступил» нет; «Кто прочитал» — бот в
списке. Не проверено: пересылка опроса в другую группу.
- @-упоминание Т от Б при заглушённой группе → пуш пробивает mute, кнопка «@» в чате.
- Реакции: режим/набор/максимум, лист «Кто поставил».
- Опрос и викторина (Т голосует, верный ответ после голоса), пересылка опроса в другую
  группу — общий счёт.
- «Кто прочитал», медленный режим (сообщение ждёт в outbox и уходит само),
  «Новичкам — без ссылок и медиа», «Скрыть участников».
- Правка, добавившая упоминание → пуш только новому упомянутому.

### 4.5. Масштаб и поиск (3.5, 3.6)

Проверено 2026-10-24 ботом (Android): поиск по сообщениям в группе со 122 сообщениями —
свежее и старое (за 120 сообщений) находятся, переход к старому открывает окно вокруг,
прокрутка в обе стороны. Не проверено: группа на 1000 участников (нужен сидер тестовых
аккаунтов на стенде), поиск участника.
- Бот создаёт группу на 1000 ботов-участников (нагрузочный режим `testpeer`), Т ищет
  участника по имени и `@username`, листает страницы.
- Поиск по сообщениям: локальные результаты сразу, серверные через ~0.4 с; переход к
  старому найденному — окно вокруг сообщения, прокрутка вверх/вниз.

### 4.6. Запрет копирования и поиск публичных групп

Проверено 2026-10-24 ботом (Android): «Запретить копирование» — нет пересылки и копирования,
скриншот чёрный, пуш «Новое сообщение» без текста; глобальный поиск находит публичные группы
по словам, тап — свой чат или предпросмотр с «Вступить».
- Б включает «Запретить копирование» → у Т нет пересылки/копирования/сохранения,
  скриншот (Android — FLAG_SECURE) блокирован; пуш без текста.
- Глобальный поиск: группы по словам названия и `@`, «N участников», тап — чат или
  предпросмотр.

## 5. Каналы (срез 4, `chats-channels.md`)

### 5.1. Базовый канал (4.1)

Проверено 2026-10-24 ботом (Android): канал с телефоном-подписчиком, пост без автора;
подписчик сразу заглушён — пуша о посте нет (`recipients=0`); после «Звук вкл.» пуш о посте
приходит в выгруженное приложение.
- Т создаёт канал, добавляет подписчиков (Б) → у Б канал **заглушён** (4.5), пуша нет.
- Посты: автор скрыт, «Подписывать сообщения» → подпись; тихий и отложенный пост.
- Подписчики видны только админам; «Скрыть подписчиков».
- Подписаться/отписаться по ссылке и `@username`, заявки.
- Б включил звук в канале → пуш о посте «Канал: текст» без «Имя:».

### 5.2. Просмотры, реакции, опросы (4.2)

Проверено 2026-10-24 ботом (Android): просмотры уникальные (повторное открытие канала не
засчитывается); `maxReactions` = 3 — четвёртую разную не даёт ни клиент, ни сервер
(`reactionsLimit`), та же реакция суммируется; опрос в канале анонимный; «Переслано из» в
«Избранном» открывает канал на посте.
- Просмотры растут при открытии постов на Т и Б (уникальные, повтор не засчитывается).
- Реакции числами, `maxReactions`; опрос анонимный.
- «Переслано из» канала → тап открывает канал на посте.

### 5.3. Комментарии (4.3)

Проверено 2026-10-24 ботом (Android): ветка с комментарием бота, ответ бота на комментарий
телефона → пуш, тап открывает ветку на ответе; мин. срок подписки 7 дней → плашка
«Комментировать можно с …» вместо поля ввода; закрыть / открыть комментарии — плашка
«Комментарии закрыты» и поле ввода меняются вживую. Не проверено: «только подписчики» для
неподписанного (нужен публичный канал — в 5.4).
- Т открывает комментарии к посту, пишет → у Б в ветке; ответ Б на комментарий Т → пуш,
  тап открывает ветку на сообщении.
- `commentsWho` / мин. срок подписки / закрытые комментарии → ошибки на экране.

### 5.4. Публичные каналы без подписки (4.4)

Проверено 2026-10-24 ботом (Android): `@testpeer_news` из поиска читается без подписки;
реакция и комментарии («только подписчики») просят подписаться; «Подписаться» — канал в
списке сразу, заглушённый. Попутно найдено: на Pixel (сборка до коммита «Ответов») в
`chatReplies` не было колонки `read` — пачки с ответами падали и журнал вставал (канал висел
с «2» при прочитанном на сервере); миграция 50 докладывает колонку, после пересборки журнал
догнался.
- Т открывает публичный канал из поиска / ссылки / «Переслано из» → читает без подписки,
  реакция — «Подпишитесь», не в списке и не в счётчике; «Подписаться» без перезагрузки.

### 5.5. Счётчик = непрочитанные чаты (4.5)

Проверено 2026-10-24 ботом (Android): 3 сообщения в группе + пост в незаглушённом канале +
личное → на вкладке 3, у строк 3 / 1 / 1; пост в заглушённом канале — серая 1, в счётчик не
входит. Не проверено: архив, серверный бейдж iOS при выгруженном приложении.
- 3 сообщения в группе + 1 пост в незаглушённом канале + личный → на иконке/вкладке 3,
  у строк — цифры сообщений; заглушённый не считается, архив — считается.
- Сверка серверного бейджа (пуш) с локальным при выгруженном приложении.

### 5.6. Пересылка в канал и «Ответы» (4.6)

Проверено 2026-10-24 ботом (Android): телефон — админ канала, пересылка в канал — пост без
автора с «Переслано от»; ответ бота на комментарий телефона → строка «Ответы» с цифрой,
1 чат в счётчике вкладки; открыл ветку — снялось; открытый экран «Ответов» получает ответы
вживую и себя не считает; «Прочитать все» в меню строки — цифра снята, счётчик −1.
- Пересылка в канал, где Т админ, — пост со скрытым автором и «Переслано из».
- Ответ Б на комментарий Т → строка «Ответы» с цифрой, 1 чат в счётчике; открыл ветку —
  снялось; «Прочитать все».

## 7. Этапы

1. **Стенд и бот:** `testAccounts` в конфиге стенда, `testpeer` (вход, стрим, звонки,
   личные сообщения), CLI. Сразу даёт ручной прогон раздела 3 с одним телефоном.
   Написано 2026-10-24 (сервер: `Config.TestAccounts`, `internal/testpeer`,
   `cmd/testpeer`; тест входа и шифрования на фейковом сервере), на стенде не проверено.
   Использование:

   ```
   # конфиг стенда (~/docker/staging-iperon/), только стенд:
   testAccounts:
     - {phoneNumber: "79990000001", verificationCode: "…"}
   # бот (из репозитория сервера):
   go run ./cmd/testpeer login -as anna -phone 79990000001 -code … -first-name Анна -last-name Бот
   go run ./cmd/testpeer call -as anna -to <userID телефона | номер> -ring 30s
   go run ./cmd/testpeer send -as anna -to <…> -text "привет"
   ```

   Номер — валидный российский мобильный (иначе сервер его не примет). Звонок
   проходит гейт «Кто может мне звонить» телефона: бот должен быть в контактах
   или разрешён. Ответ на звонок боту не виден (о нём знают только участники
   комнаты LiveKit, куда бот не входит), поэтому бот кладёт трубку по `-ring` +
   `-talk`; отказ или отбой с телефона он видит и печатает.
2. **Android-раннер:** вместо Patrol — `adb` «чёрным ящиком» (Patrol ставит свою тестовую
   сборку поверх приложения: при другой подписи release удаляется вместе со входом и базой).
   Сделано 2026-10-24: `internal/testpeer/android` (уведомления из `dumpsys notification`,
