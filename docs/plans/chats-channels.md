# Срез 4. Каналы на сервере

План 2026-10-22. Это развёрнутый «Срез 4» из `chats-groups-channels.md`. UX каналов готов в
демо, решения по нему записаны там же: подписи, «Подписаться», просмотры, комментарии и их
сроки, «Кто может комментировать», реакции с «Максимумом под постом», права админа канала.
Здесь описано, как перенести демо на сервер поверх механизмов групп (`chats-groups.md`): журнал
на чат, subject чата, `GetChatsState` / `GetChatDifference`, очередь пушей, бейдж в Redis,
`usernames` / `publicChats`, ссылки и заявки, слепой поиск.

## Что уже есть

**Клиент.** Каналы полностью работают в демо.
- Модели: `ChatType.channel`, у `Chat` — `signMessages`, `comments*`, `maxReactions`,
  `membersHidden`, `isMember`, `threadOf` / `threadPostID`; у `Message` — `authorSignature`,
  `views`, `commentsCount`, `commenters`, `commentsCloseDate`.
- Экраны работают через `ChatsDataSource`: посты полем ввода админа (`Chat.canPost`),
  «Подписаться» внизу и в ветке, вкладка «Подписчики», права админа канала
  (`_adminRightsOf`), «Изменить» с подписями и блоком комментариев.
- В `ChatsRemoteDataSource` каналы не поддержаны. `createChat`, `openComments`,
  `setCommentsClosed`, опрос вне группы и реакции вне группы бросают `_unsupported`. Поля
  `signMessages` / `comments*` / `maxReactions` в `updateChat` молча теряются. `_loadChats`
  пропускает только личные и группы.
- Журнал чата в `ChatsSync` (`planChatUpdates`) от типа не зависит. Но известные pts и
  `upsertGroup` завязаны на таблицу `chatGroups` и на `CHAT_TYPE_GROUP`.
- Шага «добавить подписчиков» при создании канала нет. «Новое» → «Канал» виден только в демо.
- Пуш с `chatTitle` показывается как групповой («Имя: текст»), признака канала нет.

**Сервер.**
- `ChatTypeChannel = 2` есть в моделях и proto, но используется только в typing.
- Групповое ветвится через `Chat.IsGroup()` (≈ 40 мест), прямые `== ChatTypeGroup`, фильтры
  Mongo `"type": ChatTypeGroup` и захардкоженный `ChatType: ChatTypeGroup` в `Update`.
- Подписчик = документ `chatMembers` (он же диалог с `readInboxMaxId`, `mutedUntil`,
  `joinedAt`). Для миллионов подписчиков такая схема годится.
- Узкие места при масштабе каналов:
  - `$inc membersCount` на документе чата при каждом вступлении;
  - реакции агрегируются `$group` при каждом чтении;
  - пуши идут 1000/с на инстанс: миллион подписчиков — около 17 минут;
  - стрим держит отдельную NATS-подписку на каждую группу;
  - JetStream `syncer` пишет в память всё `chat.*`.
- Просмотров нет нигде.

## Решения 2026-10-22

1. **Комментарии — ветка как скрытый чат.** Это поправка к решению 2026-10-08 («своя
   коллекция»).
   - Ветка — документ `chats {type: thread, parentChatId, postId}` без участников. Создаётся
     при первом комментарии (или при закрытии / открытии комментариев админом).
   - У ветки своя нумерация `messageId`, свой pts и журнал `chatUpdates`.
   - Сообщения, правка, удаление, реакции, опросы, упоминания, ответы, медиа, слепой поиск и
     история переиспользуются от групп без изменений.
   - Права берутся из канала (раздел «Комментарии» ниже).
   - Клиент уже открывает ветку как скрытый чат (`threadOf` / `threadPostID`), в списке
     диалогов её нет.
2. **Просмотры — уникальные зрители, HyperLogLog в Redis первые 7 дней.**
   - Клиент пачкой сообщает о показанных постах.
   - Первые 7 дней поста сервер считает уникальных зрителей (`PFADD`). Плотный HLL весит
     12 КБ: 70 постов в неделю у большого канала — меньше 1 МБ.
   - После 7 дней — простые приращения. От повторов защищает клиент: пост помечается
     просмотренным локально.
   - Счётчики сбрасываются в Mongo пачками. Свежие числа клиент запрашивает для видимых
     постов, в журнал они не пишутся.
3. **При создании канала есть шаг «Добавить подписчиков»** — до 200 контактов, тот же экран
   выбора, что у группы. Шаг можно пропустить. Действует приватность «Кто может добавлять
   меня в группы» (она же для каналов), отказавших сервер возвращает списком.
4. **Автор поста скрыт** (как в Telegram).
   - Подписчики получают пост без `fromUserID`. Отправителем считается канал.
   - Если включено «Подписывать сообщения», приходит `authorSignature` — имя админа на момент
     публикации, строкой.
   - Сервер хранит автора у себя: для права «править / удалять свои посты» и для закона
     Яровой.
   - Админы видят то же, что подписчики. Это проще для единой рассылки в subject.
5. **Галочек в канале нет.** `readHistory` двигает только мой `readInboxMaxId`. `readOutbox`
   и `chatReads` не пишутся, «Кто прочитал» в канале нет.
6. **Реакции в канале — только числа.**
   - «Кто поставил» не отдаётся никому, даже админам.
   - Счётчики денормализованы: `chatReactionCounts {chatId, messageId, emoji, count}` через
     `$inc`.
   - Моя реакция по-прежнему хранится в `chatReactions`: её нужно снимать и показывать.
   - Обновление в журнал канала пишется не на каждую реакцию. Пост помечается «грязным» в
     Redis, раз в 5 с одно обновление `messageReactions` несёт итоговые числа.
7. **Публичный канал читается без подписки.**
   - История, `GetChatDifference` и поиск по сообщениям доступны не подписчику публичного
     канала.
   - Пока чат открыт, клиент держит временную подписку `Chats.Watch {chatID}`, а стрим —
     subject канала. Это та же механика, что для открытой ветки комментариев.
   - Частный канал без подписки показывает только предпросмотр по ссылке, как у групп.
8. **Лимиты.**
   - Групп и каналов на пользователя — 500 вместе (`groups.maxPerUser`).
   - Подписчиков у канала — без жёсткого лимита. Конфиг `channels.maxMembers`, по умолчанию
     10 000 000.
9. **Флаг.** Всё работает только при переключателе «Каналы» на экране «Разработчик».
   Включают его capability сессии `channels` и конфиг `channels.enabled`. Схема та же, что у
   флага «Группы».

## Протокол (`protos/chats_v1.proto`)

Новые `MessageType` не заводим, только новые ветки `oneof`: `Update` — с 23, `Chats.Request`
— с 43, `Messages.Request` — с 25.

- **`ChatInfo`**:
  - `signMessages`;
  - `commentsEnabled`, `commentsTimeLimit`, `commentsWho`, `commentsMinSubscription`;
  - `maxReactions`.

  Те же поля добавляются в `EditChat` (`optional`).
- **`ChatMessage`**:
  - `views`;
  - `authorSignature`;
  - `comments {count, recentUserIDs[≤3], closeDate, closed, threadChatID}`;
  - `silent`, если ещё нет.

  У постов канала `fromUserID` пустой.
- **`CreateGroup.channel`** (сделано 2026-10-22, поле 9). Переименовывать в `CreateChat` не
  стали, чтобы не ломать клиент с флагом «Группы».
- **`ChatMessage.postOut`** (поле 16) — «этот пост мой», глазами запросившего (History / Get /
  ответ Send). Нужен для права «править / удалять свои посты»; в общем журнале — false.
- **Новые действия:**
  - `Messages.GetViews {chatID, ids[], increment}` → `[(id, views, comments)]`. Это одновременно
    регистрация просмотра и обновление чисел у видимых постов.
  - `Chats.Watch {chatID, on}` — временная подписка на публичный канал без членства или на
    ветку комментариев.
  - `Messages.OpenComments {chatID, postID}` → `ChatInfo` ветки и `Dialog`-подобное состояние
    (мой `readInboxMaxId` в ветке).
  - `Messages.SetCommentsClosed {chatID, postID, closed}`.
- **`Update.postComments {chatID, postID, count, recentUserIDs, closed}`** пишется в журнал
  канала, слитно: не чаще раза в 5 с на пост, как реакции.
- **`ChatAdminRights`:** `postMessages` / `editMessages` уже есть. Набор канала: `changeInfo`,
  `postMessages`, `editMessages`, `deleteMessages`, `banUsers`, `inviteUsers`, `manageCalls`,
  `addAdmins`. Закреп для всех — по `editMessages` (как в Telegram). Правила — общая
  таблица `channel_rights_cases.json`.
- **`PushPayload`** получает `isChannel` (поле 15): заголовок — название канала, текст
  — без «Имя:».

После правки proto скопировать в `~/GolandProjects/iperon/protos/`.

## Сервер (`iperon`)

**Обобщение групп.**
- Ввести `Chat.IsMulti()` (группа или канал) и `Chat.IsChannel()`. Пройти все `IsGroup()`,
  `== ChatTypeGroup`, фильтры `"type": ChatTypeGroup` и захардкоженные `ChatType` в `Update`
  (список мест есть в отчёте-разборе, `chats-groups.md` его не содержит).
- Где поведение общее, поставить `IsMulti()`. Где каналу нужно своё, ветвиться явно:
  - автор поста;
  - галочки;
  - реакции;
  - typing (у канала его нет);
  - слоу-мод и «новички» (только в комментариях);
  - «Скрыть историю» (у канала не бывает: подписчик видит всю ленту).
- **Права** — `channelCan` рядом с `groupCan` в `chats_groups_rights.go`. Общая таблица Go ↔
  Dart — `channel_rights_cases.json` (байт-в-байт в обоих репо). Читатель не пишет, но
  реакции и голосования доступны всем.

**Коллекции.**
- `chats`: `signMessages`, `comments*`, `maxReactions`. У ветки — `parentChatId`, `postId`,
  `closed`.
- `messages`: у поста канала — `authorId` (не отдаётся), `authorSignature`, `commentsCloseDate`,
  `threadChatId`.
- `chatViews {chatId, messageId, views}` — числа отдельно от тела. Тело сообщения после окна
  правки неизменно (основа архива).
- `chatReactionCounts {chatId, messageId, emoji, count}`.
- `membersCount` — шардированный счётчик в Redis (`members:<chat>`, `INCRBY`), раз в минуту
  сбрасывается в `chats`. Так документ канала не горячий при массовом вступлении.

**Просмотры.**
- `GetViews(increment)`:
  - пост моложе 7 дней — `PFADD views:<chat>:<msg> <userID>`, число — `PFCOUNT`;
  - старше — `INCR viewsx:<chat>:<msg>`.
- Фоновая задача раз в 30 с пишет изменившиеся числа в `chatViews` (набор «грязных» ключей в
  Redis). `PFCOUNT` + `INCR` = итог.
- Через 7 дней HLL сворачивается в число и удаляется (TTL + задача).
- Лимит частоты `getViews`; не больше 100 id за запрос.

**Комментарии.**
- `OpenComments` создаёт ветку при первом обращении. Создание идемпотентно: уникальный ключ
  `(parentChatId, postId)`.
- **Отправка в ветку** проверяет:
  - канал существует, `commentsEnabled`;
  - ветка не закрыта (`closed` или `commentsCloseDate`);
  - `commentsWho = subscribers` → я подписан и `now − joinedAt ≥ commentsMinSubscription`;
  - бан в канале;
  - «новички» и слоу-мод канала.

  Админов канала «кто / срок подписки» не касаются.
- **Права модерации в ветке** — права админа канала: удалить чужой комментарий
  (`deleteMessages`), заблокировать автора в канале.
- **Доставка.** Комментарии не рассылаются подписчикам канала. Subject ветки слушают только
  те, у кого она открыта (`Watch`). Счётчик и последние комментаторы приходят в канал слитным
  `postComments`.
- **Пуши из ветки:** ответ на мой комментарий и упоминание — только адресату.
- **Непрочитанное.** «Мои ветки» с непрочитанными ответами — позже, как раздел «Ответы» у
  Telegram. В этом срезе ветка не даёт непрочитанных в списке.

**Пуши.**
- `notifyGroupMessage` параметризуется: scope `NotifyScopeChannels`, capability
  `channels`, `isChannel`, без отправителя.
- «Тихая публикация» (`silent`) — пуш без звука, как в личных.
- Скорость: `push.channelRate` отдельно от групп. Воркер делит обход на диапазоны `joinedAt`,
  чтобы миллион подписчиков разошёлся параллельно на нескольких инстансах. Цель — 1 млн за ≤ 3
  минуты на стенде из 3 инстансов.
- Бейдж: каналы входят в бейдж, как группы (заглушённые — нет). `groupBadge` обходит группы и
  каналы.

**Живая доставка.**
- Subject `chat.<hex>` общий. Подписки стрима:
  - мои группы и каналы (≤ 500);
  - временные `Watch` (≤ 20 на сессию).
- Отдельная NATS-подписка на каждый чат при 500 чатах допустима. Если станет узким местом —
  одна wildcard-подписка на шард `chat.<shard>.*` с фильтром в памяти; в этом срезе не
  делаем.
- `chat.*` нужно убрать из JetStream `syncer`: им никто не пользуется, а каналы удвоят запись
  в память.

**Закон Яровой.** `chatAudience` для канала: `chat_id`, `channel=1`,
`recipients=membersCount`, автор поста — из `authorId`. Комментарии логируются как сообщения
ветки с `parent_chat_id`.

**Поиск.**
- `publicChats` уже хранит `type`, `SearchChats` отдаёт каналы без смены протокола.
- Слепой поиск по сообщениям канала и ветки работает как у групп. Не подписчику публичного
  канала — тоже.

## Клиент

- **Миграция 43:**
  - `chatGroups` хранит и каналы (переименовывать не будем, комментарий в коде);
  - `chatViews` не нужен: числа лежат в BLOB сообщения и обновляются из `GetViews`;
  - `chatThreads (chatID, postID, threadChatID, readInboxMaxID)`.
- **`ChatsSync`.**
  - Известные pts, `upsertGroup`, `_syncGroups`, `dialogNew` / `dialogSettings` и подсчёт
    непрочитанных — для группы и канала.
  - Флаг `channels` отдельно от `groups` (`setChannels`, capability `channels`).
- **`ChatsRemoteDataSource`:**
  - `createChat(channel)`: форма, затем «Добавить подписчиков», затем `CreateChat`;
  - `updateChat` с `signMessages` / `comments*`;
  - `setChatReactions(maxReactions)`;
  - опросы в канале (всегда анонимные);
  - `openComments` / `setCommentsClosed`;
  - `joinChat` = подписаться, выход = отписаться.

  Без сети — `ChatsOfflineException`, как везде.
- **Просмотры.**
  - Лента канала копит id постов, показанных на экране ≥ 0,5 с, и раз в 2 с шлёт `GetViews`
    с `increment` для ещё не учтённых.
  - Учтённые помечаются локально (`viewed` в BLOB / колонка).
  - Без сети очередь копится в памяти и уходит после подключения.
  - Для остальных видимых постов `GetViews` без `increment` — не чаще раза в 30 с на пост.
- **Комментарии.** Ветка открывается тем же окном чата. Сообщения ветки лежат в
  `chatMessages` под `threadChatID`, `Watch` держится, пока окно открыто.
- **Публичный канал без подписки.** Открытие из поиска или по ссылке:
  1. `Watch`;
  2. история;
  3. «Подписаться» внизу.

  Кэш таких чатов не попадает в список диалогов.
- **Пуши.** iOS NSE и `MessagePushHandler.kt` — при `isChannel` заголовок — канал, текст — без
  «Имя:». Тап открывает канал.
- **«Новое» → «Канал»** в серверном режиме — только с флагом «Каналы».

## Открытые вопросы

1. **Яровая.** Хватит ли для канала «канал + автор + число подписчиков» — тот же вопрос
