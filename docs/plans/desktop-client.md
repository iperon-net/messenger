# Десктопный клиент (macOS / Windows / Linux) — исследование

Статус: 2026-10-18 — исследование, разработка не начата. 2026-10-26 — решено: вход на
десктопе только по QR с телефона (без звонка-пароля, Яндекс ID и passkeys); первый
релиз — только сообщения (без звонков и секретных чатов), Material, macOS → Windows,
распространение с сайта, свой сбор крэшей. Все решения — §6.

## 1. Вывод

**Делать в этом же репозитории и в этом же Flutter-приложении** — добавить таргеты
`macos/`, `windows/`, `linux/`, а не заводить отдельный репозиторий.

Почему:
- Почти вся логика — чистый Dart и переносится без изменений: gRPC/стрим (`api.dart`),
  крипта (`lib/crypto/`, включая ML-KEM `pqcrypto` и секретные чаты), SQLite-кэш
  (`lib/repositories/`), синхронизация чатов (`lib/chats/`), кубиты, модели, i18n, proto.
  Это ~58 тыс. строк из ~85 тыс. (без сгенерированного); экраны — ~12 тыс. (Material)
  + ~14 тыс. (Cupertino).
- Отдельный репозиторий = либо копия этих 58 тыс. строк (и вечная синхронизация, как
  сейчас с `.proto` между клиентом и сервером), либо всё равно выносить их в общий
  пакет — то есть монорепо, только сложнее.
- Плагин без десктопной реализации не ломает сборку: он просто не регистрируется на
  этой платформе, падает только вызов (`MissingPluginException`). Значит, мобильные
  зависимости можно оставить, а вызовы — закрыть проверкой платформы.

Когда пересмотреть: если десктоп разойдётся с мобильным UI настолько, что общими
останутся только данные, — вынести ядро в пакет (`packages/iperon_core` через pub
workspaces) и сделать два приложения в одном репозитории. Начинать с этого не нужно.

## 2. Совместимость зависимостей

Платформы — из `flutter.plugin.platforms` установленных версий (pubspec.lock).

**Чистый Dart — работают везде:** material_ui, cupertino_ui, flutter_bloc/bloc, get_it,
go_router, slang, dart_mappable, grpc, protobuf, cryptography, pqcrypto, ristretto255,
dlibphonenumber, talker*, flutter_svg, lottie, animated_emoji, hugeicons,
font_awesome_flutter, flutter_boring_avatars, thumbhash, settings_ui, skeletonizer,
flutter_slidable, flutter_screen_lock, pin_code_fields, intl, objectid, sqlite_async.
SQLite с шифрованием — `sqlite3` 3.x через hooks (`source: sqlite3mc`, см. `hooks:` в
pubspec.yaml) собирается и на десктопе (нужен компилятор в CI).

**Есть macOS + Windows + Linux:** path_provider, flutter_secure_storage (Linux —
libsecret), share_plus, package_info_plus, device_info_plus, connectivity_plus,
audioplayers, wakelock_plus, url_launcher, image_picker (через file_selector — только
выбор файла), file_picker, record, emoji_picker_flutter, flutter_webrtc,
livekit_client.

**Частично:**
| Пакет | Десктоп | Что делать |
|---|---|---|
| firebase_core / firebase_remote_config | macOS, Windows (Windows у FlutterFire — «для разработки»), **Linux нет** | Конфиг на десктопе — из дефолтов + `.env`, позже с сервера; `Firebase.initializeApp` — только где есть |
| firebase_crashlytics | только macOS | На Windows/Linux — Sentry (или свой сбор логов) |
| firebase_messaging, firebase_app_installations | только macOS | Десктопу пуши не нужны: приложение живёт в трее со стримом, уведомления — локальные |
| local_auth | macOS, Windows | Разблокировка код-пароля Touch ID / Windows Hello; Linux — только PIN |

**Свои нативные каналы** (`MethodChannel`), которым нужны десктопные реализации или

`call_pip` / `call_pip_ios`, `audio_route_ios`, `device_performance`,
`system_gestures`, `video` (сжатие видео), `files` (сохранить / открыть / буфер).

## 3. Что придётся сделать именно для десктопа

1. **Платформенный слой.** `lib/platform.dart` с возможностями (`hasCallKit`,
   `hasPush`, `hasAddressBook`, `hasCamera`, `isDesktop`…) вместо разбросанных
   `Platform.isIOS / isAndroid` (их 85). В DI (`lib/di.dart`) — регистрировать
   десктопные реализации (уведомления) вместо мобильных. `main.dart`:
   Crashlytics / Firebase / PushManager / CallPush / `Calls` — только где есть.
   **Крэши — свой простой сбор** (решено 2026-10-26, Sentry не берём): на десктопе
   `FlutterError.onError` / `PlatformDispatcher.onError` (и `Logger.handle`) пишут отчёт
   (ошибка, стек, версия, ОС, последние строки лога Talker) в локальную очередь
   (SQLite), которая отправляется на сервер unary-запросом при наличии сети; сервер
   складывает в Loki (Grafana) с лейблами `platform`/`version`. На macOS Crashlytics
   технически есть, но ради одного пути на всех ОС — тоже свой сбор.
2. **UI — Material на всех ОС** (решено 2026-10-26, `macos_ui` не берём; как Telegram
   Desktop — один вид везде). Брать Material-экраны (на десктопе и так выберется
   Material — ветка «не iOS») и сделать их адаптивными, а не писать третий вариант:
   - две панели при широком окне — **уже есть** для планшетов (`SplitLayout`,
     `SplitViewMaterial`, коммит 2026-10-26): на десктопе включить `SplitLayout.enabled`
     и пересчитывать «узко/широко» при изменении размера окна (сейчас — от
     `SplitLayout.minWidth`, однопанельный режим при узком окне уже работает);
   - правый клик = контекстное меню, наведение мышью, полосы прокрутки;
   - горячие клавиши (Enter — отправить, Shift+Enter — перенос, Ctrl/⌘+K — поиск,
     Esc, ↑ — редактировать последнее);
   - drag-and-drop файлов в чат, вставка картинок из буфера;
   - окно: размер/положение (`window_manager`), трей (`tray_manager`), бейдж
     непрочитанных (Dock / иконка на панели задач), автозапуск.
3. **Уведомления.** Пушей нет — приложение держит стрим, пока запущено (в трее).
   Новые сообщения из стрима → `flutter_local_notifications` (macOS, Windows, Linux).
   Сервер уже не шлёт пуш онлайн-сессии (presence) — телефон при этом пуш получит.
4. **Вход — только по QR с телефона** (решено 2026-10-26), как в Telegram Desktop:
   десктоп показывает QR → телефон, где пользователь уже залогинен, сканирует его и
   подтверждает → сервер выдаёт сессию десктопу. Это новая серверная ручка (§4).
   **Звонок-пароль, Яндекс ID и passkeys на десктопе не делаем** — экран входа
   десктопа отдельный: только QR, без поля номера, с подсказкой «Откройте Iperon на
   телефоне → Настройки → Устройства → Подключить устройство». Войти можно, только
   имея мобильное приложение с активной сессией — осознанное ограничение. (Яндекс ID
   нужен был лишь для подтверждения номера, а здесь его подтверждает авторизованный
   телефон; `yandex_login_sdk` на десктопе и нет.) Облачный пароль (2FA), если включён,
   запрашивается на десктопе после подтверждения с телефона — через `AuthLoginCompleter`,
   как сейчас.
5. **Звонки — в первом релизе нет** (решено 2026-10-26: только сообщения). Десктоп не
   регистрирует `Calls`/`CallPush`, кнопки звонка в профиле/чате скрыты, звонки-сообщения
   в ленте показываются как обычно (без «перезвонить» — или с подсказкой «Позвоните
   с телефона»). Сервер не зовёт десктоп-сессии во входящий (§4). Звонки — отдельный
   этап после первого релиза, см. §7.
6. **Медиа.** Сжатие фото — `image`, видео — без сжатия на первом шаге (или ffmpeg),
   просмотр видео — `media_kit` на Windows/Linux, обрезка аватара — чистый Dart
   (`crop_your_image`).
7. **Секретные чаты — не делаем** (решено 2026-10-26; Telegram Desktop их тоже не
   поддерживает). Десктоп не объявляет `secretChats` в `Subscribe.capabilities`, поэтому
   сервер не выбирает его устройством для секретного чата; `SecretChatsSync` на десктопе
   не запускается, секретные чаты в списке не показываются, «Начать секретный чат» в
   меню скрыт. (Если вернёмся: крипта на чистом Dart, защита от скриншотов —
   `NSWindow.sharingType = .none` / `SetWindowDisplayAffinity`.)
8. **Хранение.** Ключ БД — Keychain (macOS, нужны entitlements), DPAPI (Windows),
   libsecret (Linux). Пути в БД — только относительные (iOS меняет путь к контейнеру при обновлении —
   то же правило для десктопа).
9. **Сборка и выпуск — только с сайта** (решено 2026-10-26, Mac App Store и
   Microsoft Store не используем: песочница App Store мешает трею/автозапуску/
   автообновлению). macOS — Developer ID-подпись + нотаризация, DMG; Windows —
   установщик (Inno Setup или MSIX вне Store) + сертификат подписи кода. Скачивание с
   iperon.net. Автообновление — `auto_updater` (Sparkle / WinSparkle) с appcast на
   сайте. CI — отдельные задания на macOS / Windows раннерах (сейчас CI только iOS).

## 4. Сервер

- Вход по QR — единственный новый способ входа для десктопа (новая пара ручек: создать
  токен входа → подтвердить с телефона → выдать сессию десктопу через стрим). Токен
  короткоживущий и одноразовый; телефон перед подтверждением показывает, какое
  устройство входит (платформа, имя, город по IP).
- Платформа/тип устройства в сессии (для «Устройств» и решений о пушах).
- Звонки: не звать десктоп-сессии во входящий (по типу устройства или по отсутствию
  capability звонков в `Subscribe`); у звонящего ничего не меняется — звонит телефон.
- Секретные чаты: устройство для секретного чата выбирается только среди сессий с
  capability `secretChats` — проверить, что десктоп не может оказаться выбранным.
- Крэш-репорты: unary-ручка приёма отчёта → Loki (лимит частоты и размера).
- Остальное (стрим, presence, чаты) — без изменений.

- Секретные чаты на десктопе — не делаем (§3.7).

## 7. Звонки на десктопе (после первого релиза)

Решено 2026-10-26: первый релиз без звонков, затем — полноценные звонки в самом
десктопном приложении (как Telegram Desktop). Отвергнуто: «только исходящие» /
«только демонстрация экрана» — экономия мала, а поведение непонятно пользователю.

База уже есть: `livekit_client` и `flutter_webrtc` работают на macOS и Windows,
сигналинг — по тому же стриму (`protos/call_v1.proto`), сервер почти не меняется.
Пушей нет — звонок доходит, только пока приложение запущено (хотя бы в трее); для
компьютера это нормально.

**Шаг 1 — звонки 1-на-1 (аудио + видео).**
- Платформенный слой: на десктопе регистрировать `Calls`, но без `CallPush` /
  CallKit / `flutter_callkit_incoming`; нативные каналы `call_window`, `call_audio`,
  `system_call`, `audio_devices`, `call_pip*`, `audio_route_ios` — заглушки или
  десктопные реализации.
- Входящий: своё окно поверх остальных (`window_manager`: always-on-top, фокус) +
  системное уведомление (`flutter_local_notifications`) + рингтон (`audioplayers`).
- Мультидевайс: входящий звонит и на телефоне, и на десктопе; ответил один — на
  остальных гаснет сигналом `CALL_ACCEPT` (написан, не проверен на устройствах —
  проверить заодно). Сервер (§4): снять запрет «не звать десктоп-сессии», звать
  только онлайн-сессии с capability звонков в `Subscribe`.
- macOS: entitlements `com.apple.security.device.audio-input` / `camera` (hardened
  runtime, без них нотаризованная сборка не получит доступ) +
  `NSMicrophoneUsageDescription` / `NSCameraUsageDescription` (локализованные).
- Окно звонка — отдельный экран/окно вместо PiP (iOS PiP на десктопе не нужен).
- Проверить: E2EE звонков (FrameCryptor) на macOS/Windows и смешанный звонок
  десктоп ↔ телефон; поведение краша LiveKit/WebRTC 0x28 (upstream livekit #1186)
  на десктопе; эхоподавление на встроенных динамиках ноутбука.

**Шаг 2 — устройства и демонстрация экрана.**
- Выбор микрофона / камеры / динамика (`Hardware.instance` LiveKit), переключение
  на лету, реакция на подключение/отключение гарнитуры.
- Демонстрация экрана: на десктопе проще, чем на мобильных (без Broadcast Extension
  / MediaProjection) — выбор экрана/окна через `desktopCapturer` flutter_webrtc.
  Рецепт мобильной реализации — откат 2026-09-24 (revert dd334ce); macOS требует
  разрешения «Запись экрана».

**Шаг 3 — «Принимать звонки» по устройствам** (в «Устройствах», как в Telegram).
Общая настройка для всех платформ, не только десктопа: пользователь сам выбирает, на
какие устройства не должны приходить входящие (например, рабочий ноутбук или
планшет).
- Proto (`device_sessions_v1.proto`): в `DeviceSession` — поле `acceptCalls` (bool,
  по умолчанию true); новый запрос `DeviceSessionsSetAcceptCalls { sessionID, accept }`.
  Можно менять для любой своей сессии, включая текущую.
- Сервер: флаг хранится в сессии; рассылка входящего (стрим + VoIP/FCM-пуши)
  пропускает сессии с `acceptCalls = false`. После изменения — push `DEVICE_SESSIONS`
  на все сессии пользователя (тот же паттерн, что у приватности). Если звонки
  выключены на всех устройствах — звонящий получает «недоступен», как при отсутствии
  онлайн-сессий; исходящие с такого устройства работают как обычно.
- Клиент: в «Устройствах» у каждой сессии (и у текущей) переключатель «Принимать
  звонки» — Cupertino и Material; значение из кэша `deviceSessions` (видно offline),
  запись — серверная unary с гардом `hasNetwork()`, без оптимистичного отката.
- Десктоп: тот же переключатель; до шага 1 у десктоп-сессий он недоступен
  (звонков там ещё нет — сервер всё равно их не зовёт).

**Позже — перенос звонка между устройствами** (своё отличие, в Telegram нет):
ответил на телефоне → «Перевести на компьютер» (и обратно). С LiveKit — второе
устройство входит в ту же комнату, первое выходит, собеседник не замечает. Нужны:
серверный сигнал передачи звонка сиблинг-сессии, выдача ей токена в ту же комнату,
UI на обеих сторонах. Строится поверх шагов 1–2.

## 8. Итоги спайка macOS (этап 0, 2026-10-26)

Работает: сборка и запуск (debug), вход по тестовому номеру + облачный пароль,
стрим (`connected`), синхронизация чатов, две панели (`SplitLayout` на десктопе),
служебный чат (уведомление о входе показывает «macOS 26.x»), отправка текста в
«Избранное» и личный чат. Вложения (выбор файла, загрузка на CDN) — не проверены.

Что понадобилось (в коде):
- Таргет `macos/`: bundle id `net.iperon.messenger`, имя Iperon, **macOS 14.0+**
  (`passkeys` требует 13.5+); песочница выключена (только сайт — §3.9), окно
  1100×760 по умолчанию, размер/положение запоминает AppKit (`setFrameAutosaveName`).
- `lib/platform.dart` — `AppPlatform` (`isDesktop`, `hasFirebase`, `hasPush`,
  `hasCalls`, `hasSecretChats`) — начало этапа 1.
- Firebase только на мобильных: `main.dart` (`_initFirebase`), `Settings` берёт
  значения из `_defaults` + `.env` вместо Remote Config; плитка «Обновить Remote
  Config» скрыта.

## 13. Итоги этапа 4 — вход по QR (2026-10-26; сервер 60bb31f, клиент 520e400)

Проверено: десктоп (macOS) ↔ телефон на стенде — QR, подтверждение, вход.

- **Протокол** — `protos/qr_login_v1.proto`: `AUTH_QR` (pre-auth, unary;
  `newToken` с данными устройства → токен 32 байта и срок; `poll` → PENDING /
  ACCEPTED с confirmationSession / EXPIRED) и `AUTH_QR_CONFIRM` (телефон, с сессией:
  `accept=false` — кто входит, `true` — впустить; истёкший — `qrLogin.expired`).
  QR — `iperon://login?token=<base64url>` (`qrLoginData` / `parseQrLoginToken`).
- **Сервер** — `internal/services/auth_qr.go`: запись токена в redis
  `authQr:<sha256(token)>` (зашифрована, TTL 1 мин; город по IP десктопа),
  подтверждение выпускает обычную `authConfirmation` (как Яндекс: `LoginMethod
  = qr`, облачный пароль не пропускается), подтверждённый вход отдаётся десктопу
  один раз. Нового пользователя путь не создаёт. Обработчики — `internal/api/qr_login.go`.
- **Десктоп** — `/auth` на десктопе = `AuthDesktopMaterial` (`auth_qr_material.dart`,
  `AuthQrCubit`): QR + 3 шага, опрос раз в 2 с, новый токен за 10 с до срока, дальше
  облачный пароль или `AuthLoginCompleter`. В debug — ссылка «Войти по номеру».
- **Телефон** — «Устройства» → «Подключить устройство» (`DeviceLinkCupertino` /
  `DeviceLinkMaterial`, логика — `device_link_common.dart`, сканер `mobile_scanner`):
  подтверждение с моделью, ОС и городом, ошибки — устаревший / чужой QR, нет сети,
  нет камеры.
- Не сделано: QR-вход в мультиаккаунт («Добавить аккаунт» на десктопе — тот же
  экран, не проверялся), лимит частоты `newToken` по IP.
