# 02-delete-service-messages — удаление служебных сообщений в группах и каналах

**Статус:** done (2026-11-14)

## Цель

Дать администрации группы/сообщества/канала (владельцу и админам с правом
«удалять сообщения») возможность удалить служебное сообщение — центрированную
плашку («Иван вступил в группу», «Анна закрепила «…»», «Название изменено» и
т.п.) — у всех участников, как обычные сообщения: через long-press меню, с
эффектом «пыли» и синхронизацией на другие устройства. Обычный участник
служебные не удаляет. Как устроены служебные сообщения (исследование
2026-11-13): служебность — не флаг и не тип, а один из служебных членов oneof
в зашифрованном контенте (`MessageContent`: `chatAction`, `pin`; личные —
`call`, `ttlChanged`, `noForwards*`); в каналах служебные о составе участников
не пишутся вовсе, там только «название/фото сменилось» и «закрепил сообщение».
Вся механика удаления (RPC `Messages.Delete` → `Update.DeleteMessages` →
`ChatsSync._deleteLocally`, пыль, offline-гарды) готова с обеих сторон —
не хватает политики прав, UI-пункта на плашках и ослабления `canDelete`.

## Принятые решения

- **Группа/сообщество: удаляют только владелец и админы с правом «удалять
  сообщения» (`deleteMessages`), независимо от того, кто вызвал действие** —
  обычный участник не может удалить даже своё служебное (как в Telegram).
  Ответ пользователя (AskUserQuestion 2026-11-13). Требуется серверная правка:
  сегодня `checkDeleteForAll`
  (`~/GolandProjects/iperon/internal/services/chats_groups.go:1806-1847`)
  разрешает автору-не-админу удалить своё служебное (`default: allowed = true`
  — ветка «своё в группе»); клиент просто прячет кнопку
  (`ChatCubit.canDelete`, `lib/cubit/chat/chat_cubit.dart:1125` —
  `!message.service`). Реализация: для служебных (`isServiceContent`,
  `internal/services/chats_pins.go:373-388`) всегда проверять право
  `groupActionDeleteOthers`. Альтернатива отклонена: «автор или админы» —
  обычный участник смог бы убирать следы собственных действий (свою плашку
  «вступил в группу»), а единое правило «служебные убирает администрация»
  проще и предсказуемее.
- **Канал: политика без изменений** — служебное считается «чужим»: владелец и
  админы с правом «удалять сообщения». Ответ пользователя (2026-11-13).
  Клиент уже так считает (`canDeleteChannelPost`,
  `lib/chats/channel_rights.dart:75-77`: `message.service` →
  `ChannelAction.deleteOthers`), сервер — тоже (комментарий «Служебные в
  канале — как чужие»). Нюанс для шага сервера: у автора-админа своё
  служебное в канале сегодня может пройти по ветке «свой пост»
  (`channelActionDeleteOwn`, право «публиковать») — для служебных
  унифицировать на `deleteOthers`, чтобы клиент, сервер и фикстуры прав
  совпадали.
- **Мультывыделение не трогаем**: служебные в режиме выделения не участвуют
  (как в Telegram), удаляются по одному через меню плашки. Ответ пользователя
  (2026-11-13). Альтернатива отклонена: выделение плашек требует новой ветки
  тапа/кружков в ленте ради редкого сценария массовой чистки.
- **Удаление всегда «у всех»** — как у обычных сообщений в группе/канале
  (`_askDelete`, `lib/screens/chats/chat_cupertino.dart:319-338`, возвращает
  `!chat.isSelf`); «только у себя» для служебных не делаем.
- **Скоуп этапа: группы, сообщества, каналы.** Служебные личных чатов (звонок,
  автоудаление, запрет копирования + интерактивный запрос
  `noForwardsRequest` с кнопками) не трогаем вовсе — удаление служебных в
  личных чатах не делаем ни в этом этапе, ни позже (решение пользователя
  2026-11-13). `systemNotice` (системный аккаунт «Iperon») — обычный
  пузырь с кнопками, не плашка — вне этапа.
- **Удаление плашки «закрепил сообщение» не снимает сам закреп**: закреп —
  отдельные строки (`chatPins` на сервере — включая shared, `chatPinned` на
  клиенте), плашка — только анонс в ленте; плашка над лентой
  (`PinnedMessageBar`) остаётся. Тап плашки по закрепу (переход к сообщению)
  сохраняется.
- **Клиентская спецификация.** Схема SQLite не меняется (служебность внутри
  `chatMessages.content` BLOB) — миграций нет. Слои: права —
  `ChatCubit.canDelete` + `group_rights.dart`/`channel_rights.dart` как
  единая таблица; UI — `message_bubble.dart` (ветки плашек `:288-330`:
  добавить `keyFor` — нужен для «пыли»/удержания места, сейчас есть только у
  части плашек — и menu-обвязку), пункты меню в `chat_cupertino.dart`
  (`_menuActions`, `:885-1004`) и Material action sheet
  (`chat_material.dart`, `:960-1128`), удаление — существующий
  `deleteWithDust` (`chat_common.dart:1613-1636`) → `ChatCubit.delete` →
  `ChatsDataSource.deleteMessage` (`chats_remote_data_source.dart:3178-3193`)
  → `Update.DeleteMessages` → `ChatsSync._deleteLocally`. Cupertino/Material
  синхронно, общая логика — в `chat_common.dart`. Новые строки i18n — только
  через `lib/i18n/en.i18n.yaml` + `ru.i18n.yaml` и `dart run slang`.
- **Демо-источник** должен заработать через общий `deleteMessage`
  (`lib/demo/chats_demo_data_source.dart:2025-2029`) после ослабления
  `canDelete`; проверяется юнит-тестами.
- **Совместимость версий:** старый сервер уже разрешает админам удалять
  служебные (право `deleteOthers`), новый сервер только запрещает их
  не-админам; новый клиент со старым сервером корректен. Пуш сервера раньше
  клиента — как для связанных изменений.
- **Что НЕ делаем в этом этапе:** служебные личных чатов (не делаем вовсе —
  решение пользователя 2026-11-13), `systemNotice`,
  выделение плашек, «удалить только у себя» для служебных, изменения
  протокола (RPC и `Update.DeleteMessages` подходят как есть), новые
  pub-зависимости, правки `ChatsSync`/репозитория.

  внешний long-press прикрепляется только без обёртки (Material path), с

  виджет-тесты (`test/components/chat_messages_view_test.dart`): экран не
  перехватывает long-press при обёртке, long-press открывает меню
  (100+800 мс — анимация decoy 800 мс), Material-путь без обёртки.
  (commit 5bc7910)
- [x] 6. macOS (десктоп): у плашки не было обработчика правого клика — у

  `DesktopPointer.last` → меню у курсора); добавлен в `servicePill`,

  (`chat_messages_view_test.dart`). (commit 1992d08)
- [x] 7. iOS (reopen, 2026-11-14, сборка `v0.0.654`): decoy-фаза

  тест валидирован откатом). Action sheet/свой лифт удалены как
  отклонённые. Тесты: обёртка + копия без конфликта ключей, fallback
  long-press, правый клик десктопа (`chat_messages_view_test.dart`).

## Открытые вопросы

- ~~Кто может удалять служебные сообщения в группе?~~ — **решено:** только
  владелец и админы с правом «удалять сообщения», независимо от того, кто
  вызвал действие (ответ пользователя 2026-11-13, AskUserQuestion).
- ~~Кто может удалять служебные сообщения в канале?~~ — **решено:** как
  сейчас — служебное считается «чужим», право «удалять сообщения» (ответ
  пользователя 2026-11-13).
- ~~Включать ли служебные в режим выделения (массовое удаление)?~~ —
  **решено:** нет, только одиночное удаление через меню плашки (ответ
  пользователя 2026-11-13).
- ~~Удаление служебных в личных чатах (звонки, автоудаление, запрет
  копирования + интерактивный запрос)?~~ — **решено:** не делаем вовсе, ни в
  этом этапе, ни в будущем (решение пользователя 2026-11-13); скоуп этапа —
  только группы, сообщества, каналы.
