# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A Flutter messenger app (Android + iOS, Firebase project `iperon`, product name "Iperon"). The UI is Cupertino-first. Beyond the app scaffolding (logging, DI, Firebase, cubit/bloc state) it already wires up a gRPC/protobuf backend client, an encrypted SQLite store, a hybrid classical + post-quantum key exchange, phone-number auth, and slang-based i18n. The backend host defaults to `staging.iperon.net:443`.

## Commands

- `flutter pub get` — install dependencies.
- `flutter run` — run the app on a connected device/emulator. Debug builds load `.env.development` (see Settings below); an unencrypted DB is used in debug, an encrypted one in release.
- `flutter analyze` — static analysis (uses `analysis_options.yaml`, based on `flutter_lints`).
- `flutter test` — run tests (there are no tests yet under `test/`).
- `flutter test test/some_test.dart` — run a single test file.
- `dart run build_runner build --delete-conflicting-outputs` — regenerate `dart_mappable` code (`*.mapper.dart` files under `lib/models/` and `lib/cubit/`). Run this after changing any `@MappableClass()` model. `dart_mappable_builder` runs under this builder. (`envied_generator` is present in `dev_dependencies` but there is currently no `@Envied` usage under `lib/` — runtime config comes from `Settings`/dotenv/Remote Config instead.)
- `dart run slang` — regenerate i18n code (`lib/i18n/translations*.g.dart`) from the `lib/i18n/*.i18n.yaml` sources (config in `slang.yaml`). Run after editing translations.
- Protobuf: the `*.pb*.dart` under `lib/protobuf/` are generated from the `.proto` files in `protos/` at the repo root via `protoc` (no in-repo script). Do not hand-edit the generated Dart.

Note: `taskfile.yml` at the repo root is for an unrelated Go backend project and does not apply to this Flutter codebase — ignore it.

## Architecture

- **Dependency injection**: `lib/di.dart` uses `get_it` as a service locator (`getIt`). Singletons are registered async via `registerCommonDependencies()`, called once at app startup in `main.dart` before `runApp` (which then `await getIt.allReady()`). The full service graph, in dependency order: `Logger` → `Settings` → `Repositories` → `Auth` → `Routers`, plus `Utils` (no deps), `API` (`dependsOn: [Settings]`) and `Crypto` (`dependsOn: [Settings, Utils]`). Add new app-wide services here following the existing `Logger` pattern (`registerSingletonAsync` + guarded by `isRegistered`), and mirror them in `unregisterCommonDependencies()`.
- **Utils**: `lib/utils.dart` holds `Utils` (registered in `get_it`). It centralizes phone-number normalization via `dlibphonenumber` (`phoneNormalization` — RU-centric: rewrites a leading `8` to `7` and treats bare 10-digit `9XXXXXXXXX` as a Russian mobile, returning a `PhoneNumberModel` with `international`/`national`/`e164`/`rfc3966`; invalid input yields an all-empty model, never throws), `bytesToHex`/`hexToBytes`, and async `packageInfo()`/`deviceInfo()` (via `package_info_plus`/`device_info_plus`/`device_marketing_names`).
- **Logging**: `lib/logger.dart` wraps `package:talker` in a `Logger` class exposing `debug/info/warning/error/critical/handle`. Always fetch it via `getIt.get<Logger>()` rather than constructing a new `Talker` directly. `handle()` is the intended entry point for reporting caught exceptions (mirrors Talker's `handle`).
- **Crash reporting**: `main.dart` wires both `FlutterError.onError` and `PlatformDispatcher.instance.onError` to `FirebaseCrashlytics.instance` so both framework and platform-level errors are reported.
- **State management**: uses `flutter_bloc`/`bloc` cubits. Convention: one cubit class + one immutable state class per feature, under `lib/cubit/<feature>/` (see `lib/cubit/common_cubit.dart` + `lib/cubit/common_state.dart` as the template). State classes use `dart_mappable` (`@MappableClass()` + `with <State>Mappable` + `part '<file>.mapper.dart'`) for `copyWith`/equality codegen — remember to run `build_runner` after editing them. Cubits are plain classes (not registered in `get_it`); state carries a `Status` enum (`initialization`, `loading`, `success`, from `lib/constants.dart`) to track async lifecycle.
- **Barrel exports**: `lib/cubit.dart` re-exports `lib/cubit/cubit.dart`, which re-exports individual cubit files — import cubits via `package:messenger/cubit.dart` and add new cubits to `lib/cubit/cubit.dart`'s export list.
- **Auth / routing guard**: `lib/auth.dart` holds `Auth`, the single source of truth for "is the user logged in". It is registered in `get_it` (`dependsOn: [Repositories]`) and loads the active session from SQLite **once** at startup via `repositories.sessions.getActive()`; `isAuthorized` is then read from memory. `lib/routers.dart` wires it into both `GoRouter`s through `redirect` (sends anonymous users to `/auth`, keeps logged-in users out of `/auth`) plus `refreshListenable`. `redirect` *can* be async in go_router, but it runs on every navigation — hence the in-memory cache instead of hitting the DB per transition. After writing a session to the DB, call `getIt.get<Auth>().refresh()` so the router re-evaluates the route (see `lib/cubit/auth/auth_moderation_application_store_cubit.dart`). The `_common` routes use a `StatefulShellRoute.indexedStack` for the bottom tab bar (`/contacts`, `/calls`, `/chats`, `/settings`) rendered by `HomeCupertino`; sub-screens like `/settings/language` and `/settings/appearance` are declared as nested `routes:` but pin `parentNavigatorKey: rootNavigatorKey` so they push full-screen over the tab bar. Navigate with `context.go(...)`.
  - **Push routes MUST use `pageBuilder:` with `CupertinoPage` from `cupertino_ui`, not `builder:`.** The app is wrapped in `CupertinoApp` from `package:cupertino_ui` (the decoupled UI package), *not* `package:flutter/cupertino.dart`. For a `builder:`-only route, go_router auto-picks the `Page` type by `findAncestorWidgetOfExactType<CupertinoApp>()` against Flutter's built-in `CupertinoApp` — which never matches the `cupertino_ui` one, so it silently falls back to `NoTransitionPage` (no iOS transition, **no swipe-back gesture**). Use the `_page(state, child)` helper in `lib/routers.dart` (returns a `cupertino_ui` `CupertinoPage`) for any full-screen push. The tab-root routes stay on `builder:` since they're never pushed and don't need a swipe.
- **Firebase**: configured via FlutterFire (`lib/firebase_options.dart`, generated — do not hand-edit; regenerate with `flutterfire configure` if project settings change). Crashlytics wiring lives in `main.dart`; Remote Config is initialized in `lib/settings.dart` (see below).
- **Settings / config**: `lib/settings.dart` holds `Settings`, registered in `get_it` (`dependsOn: [Logger]`). It is the single accessor for runtime config and layers two sources: `flutter_dotenv` (`.env`, plus `.env.development` in debug) takes precedence, falling back to Firebase Remote Config (1-hour min fetch interval; defaults live in the `remoteConfig.setDefaults({...})` map here — add new remote-config keys there). Read config through `Settings` getters (`apiHost`, `apiPort`, `databaseName`, etc.); don't touch `dotenv`/`remoteConfig` directly elsewhere.
- **gRPC / API**: `lib/api.dart` holds `API`, registered in `get_it` (`dependsOn: [Settings]`). It builds a single `IperonClient` (from `lib/protobuf/protos/v1.pbgrpc.dart`) over one long-lived `ClientChannel` with keep-alive + jittered exponential backoff, and logs traffic via `TalkerGrpcLogger`. Two usage patterns:
  - **Unary RPCs**: `API.call(() => client.someRpc(...))` wraps the call, maps `GrpcError` codes to an `APICallStatus` (`APIStatus.success|error` + `statusCode` + a message/i18n-key `error`), and never throws for gRPC errors.
  - **Long-lived bidirectional stream**: `API` also owns the app's persistent `client.stream(...)` (the `rpc Stream` in `v1.proto`). It is opened/closed by `_reconcile()`, gated on two flags — set `setAuthorized(bool)` and `setForeground(bool)` (driven from `AppLifecycleState` in `main.dart`); the stream only stays open while both are true. On open it sends a `Subscribe` message (`_subscribe()`). Connection state is surfaced as `ApiConnectionStatus` (`connecting|updating|connected`) via `connectionStatus` + `connectionStatusStream`. Consume inbound traffic by message type through `api.on(MessageType)` (a filtered broadcast `Stream<Uint8List>`) rather than touching the raw stream.
  - The commented-out block at the bottom is a reference for the intended TLS/metadata/`callOptions` setup — the current channel uses `ChannelCredentials.insecure()`.
- **Persistence (encrypted SQLite)**: `lib/repositories/` holds `Repositories`, registered in `get_it` (`dependsOn: [Settings]`). It opens one `sqlite_async` `SqliteDatabase` in the app-support dir and exposes typed repository objects (`settingsDevice`, `users`, `sessions`, `deviceSessions`) — each defined as a `part` file of `repositories.dart` (`cache.dart`, `settings_device.dart`, `users.dart`, `sessions.dart`, `device_sessions.dart`). Note the two distinct "session" concepts: `sessions` is the **local** auth session (drives `Auth`), while `deviceSessions` mirrors the user's **remote** active devices fetched over gRPC (`device_sessions_v1.proto`) for the settings screen. In release builds the DB is encrypted (SQLCipher `PRAGMA key`) with a random password persisted in `flutter_secure_storage`; in debug it's unencrypted. `foreign_keys = ON` is set per connection. **Schema changes go through `migrations.add(SqliteMigration(n, ...))` in `_initialization()`** — never edit an existing migration. `Settings.isDeleteDatabase` (env `IS_DELETE_DATABASE`) wipes the DB + stored password on launch.
- **Models vs. state**: `lib/models/` holds `@MappableClass()` data models (`Session`, `User`, `SettingsDeviceModel`, enums like `ColorThemeModel`/`DarkModeModel`, …) with generated `*.mapper.dart` — these are what repositories read/write. `lib/models/mapper.dart` registers custom `dart_mappable` mappers (`Uint8ListMapper`, `BoolMapper`) that bridge SQLite BLOB↔`Uint8List` and int↔`bool`; new models storing those types rely on these. Cubit *state* classes (`lib/cubit/**/*_state.dart`) are separate — see the state-management convention above.
- **Crypto**: `lib/crypto/` holds `Crypto`, registered in `get_it` (`dependsOn: [Settings, Utils]`), exposing `keyExchange` (`lib/crypto/syncer.dart`, a `part` of `crypto.dart`). It combines classical (`package:cryptography`) with post-quantum ML-KEM (`package:pqcrypto`) for a hybrid key exchange — session `sharedKey`/`salt` end up in the `sessions` table.
- **Background tasks & push (not yet wired)**: `native_workmanager` and `firebase_messaging` are declared in `pubspec.yaml`, but the actual wiring is currently commented out — the `@pragma('vm:entry-point')` background worker and `NativeWorkManager.initialize/registerDartWorker/enqueue` calls in `main.dart`, and there is no `FirebaseMessaging` handler yet. Don't look for an existing integration; a background worker must re-run `registerCommonDependencies()` since it starts in a fresh isolate (see the commented `helloWorldWorker` reference in `main.dart`).
- **i18n (slang)**: translations are authored in `lib/i18n/en.i18n.yaml` / `ru.i18n.yaml` and compiled to `lib/i18n/translations*.g.dart` (run `dart run slang`). `main.dart` wraps the app in `TranslationProvider`; the active locale is persisted in `settingsDevice.locale` and applied via `LocaleSettings`. English is the base/fallback locale.
- **App passcode & biometric lock**: an optional local app-lock, separate from server auth. The PIN is hashed with **Argon2id** (`package:cryptography`) and only the hash is persisted in `settingsDevice`; the create flow (`SettingsPasscodeCreateCubit`) and the verify flow (`SettingsPasscodeCubit`) **must use identical Argon2id parameters** (`parallelism/memory/iterations/hashLength`) or entered PINs will never match. The lock UI uses `flutter_screen_lock`; biometric unlock uses `local_auth` (`LocalAuthentication`) and is triggered from `main.dart`'s `didChangeAppLifecycleState` (lock on `paused`/`hidden`, prompt on `resumed`) — the app root is a `WidgetsBindingObserver`.
- **Connection status UI**: `ConnectionCubit` (`lib/cubit/connection_cubit.dart`) merges two independent signals into one status for the UI — device network reachability (`connectivity_plus`) and the gRPC stream state (`API.connectionStatusStream`). Like other cubits it is not in `get_it`; a single instance is provided high in the shell so all tabs share the same status (rendered by `lib/components/connection_title.dart`).
- **UI (Cupertino-first)**: screens live under `lib/screens/**` named `*_cupertino.dart`; `main.dart` runs a `CupertinoApp.router`. Theming is in `lib/themes/cupertino.dart` (`ThemesCupertino`), driven by `settingsDevice.colorTheme` + `darkMode` from `CommonCubit` state. `lib/routers.dart` keeps route lists split into `_common` (shared) plus empty `_cupertino`/`_material` slots so a Material variant can be added later.
- **Extensions**: `lib/extensions/` holds Dart `extension`s on built-in types, barrel-exported via `lib/extensions.dart` (import through `package:messenger/extensions.dart`). Notably `DateTime.relativeFormat(t)` (`date_time_extensions.dart`) renders localized "today/yesterday/dd.MM.yyyy at HH:mm" strings via slang, and `String.capitalize()`.

## CI/CD

GitHub Actions live in `.github/workflows/`. `lib/firebase_options.dart` and the `.env` files are gitignored, so CI reconstructs them from secrets before building — mirror that if you add a workflow.
- **`code_checks.yaml`** (PRs/pushes): `flutter pub get` → restore `firebase_options.dart` from a secret → generate `.env` assets → `dart format --output=none --set-exit-if-changed lib` (formatting is enforced — run `dart format lib` before pushing) → `flutter analyze`.
- **`deploy_ios.yaml`** (on `v*` tags): builds a release IPA and uploads to TestFlight via fastlane. `BUILD_NAME` comes from the tag (`v0.0.1` → `0.0.1`); `BUILD_NUMBER` is a UTC `date` timestamp so it stays unique and monotonically increasing.

## TODO

- **Force-logout when the server revokes a session.** `Auth.isAuthorized` currently only means "there is an active row in the local `sessions` table" — it is never validated against the server. If the server revokes a session, the app finds out only on the next gRPC call, and the user keeps sitting on the current screen. Plan: handle the auth-error response in `API.call` (`lib/api.dart`) by calling `getIt.get<Auth>().logout()`. This is exactly why `Auth` extends `ChangeNotifier` and the routers pass it as `refreshListenable` — background code has no `BuildContext`, so `notifyListeners()` is what makes go_router re-run `redirect` and kick the user to `/auth` without any navigation call. Do not drop the `ChangeNotifier` base class as "unused": the in-app login/logout paths navigate explicitly and would work without it, but this scenario cannot.
- **Second login workflow is unfinished.** `AuthCubit.onPressed` (`lib/cubit/auth/auth_cubit.dart`) only logs the call-password response and never creates a session. When it is completed, it needs the same `await getIt.get<Auth>().refresh()` as the moderation-store flow.
- **`users.salt` column is missing.** `Users.setSalt` runs `UPDATE users SET salt = ?`, but migration 1 creates `users` with only `userID` and `phoneNumber`, so the statement fails with `no such column: salt`. Needs a migration 2 adding `salt BLOB`.
